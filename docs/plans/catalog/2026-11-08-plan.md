# 1. Context

**Problem:**
Phân hệ Thực Đơn & Món Ăn (Catalog Module) là thành phần lõi điều phối dữ liệu sản phẩm, phân cấp nhóm món (Categories ➜ Subcategories ➜ Products), nhóm tùy chọn kèm món (Size, Topping, Mức đường, Lượng đá) và banner tiếp thị theo mùa cho cả Mobile Web PWA và Kiosk Touchscreen POS. Hiện tại tầng database và DDL Flyway (`V5__create_catalog_and_modifiers.sql`, `V10__seed_demo_data_linn_sushi.sql`) đã sẵn sàng nhưng tầng Backend Java Spring Boot chưa được hiện thực hóa đầy đủ theo chuẩn Clean Architecture 4 lớp.

**Affected Modules:**
- `com.ordera.modules.catalog` — Hiện thực hóa trọn vẹn 4 tầng (Domain, Application, Infrastructure, Presentation) cho 6 API nghiệp vụ.
- `com.ordera.modules.tenant` — Tái sử dụng `StoreRepository` để xác thực tính hợp lệ của chi nhánh `storeId` theo `tenantId`.
- `com.ordera.common` — Tái sử dụng `ApiResponse<T>`, `TenantContext`, `SecurityUtils`, `ErrorCode`, `BusinessException`.

**Non-Goals:**
- Chưa triển khai API quản trị CRUD thực đơn cho Merchant Portal (sẽ làm trong phân hệ Admin/Backoffice riêng).
- Chưa tích hợp thanh toán đơn hàng (thuộc phân hệ Order/Checkout).
- Chưa xử lý trừ điểm đổi voucher (thuộc phân hệ Reward).

# 2. Constraints

**Language & Framework:** Java 21 LTS, Spring Boot 3.3.5 (Spring Data JPA, MapStruct 1.5.5.Final, Lombok, Jakarta Validation).  
**Architecture:** Clean Architecture 4 lớp (Presentation ➜ Application ➜ Domain ➜ Infrastructure).

**Rules:**
- **Độc lập tầng Domain:** Tầng `domain/` hoàn toàn là Pure Java POJOs, cấm phụ thuộc vào Spring Framework (`@Service`, `@Component`, `@Autowired`) hay JPA/Hibernate (`@Entity`, `@Table`, `@Column`).
- **Xử lý ngoại lệ chuẩn hóa:** Cấm tạo Exception classes riêng lẻ. Mọi lỗi nghiệp vụ catalog đều định nghĩa trong `CatalogErrorCode` (implement `ErrorCode`) và ném qua `BusinessException`.
- **Phân lập Multi-Tenant:** 100% các truy vấn cơ sở dữ liệu phải được lọc theo `tenantId` lấy từ `TenantContext.getTenantId()`.
- **Orchestrator Pattern:** Các UseCase `execute()` chỉ giữ vai trò điều phối các bước, phân rã logic ghép cây và duyệt modifier thành các private helper methods.

**Performance Budgets:**
- Latency: Trả về cây thực đơn phân cấp < 100ms.
- Tối ưu N+1 Query: Sử dụng batch query (`findByCategoryIdIn`, `findByGroupIdIn`) thay vì truy vấn trong vòng lặp lồng nhau.

# 3. Conventions

**Naming:**
- Classes: `PascalCase` — `Category`, `Product`, `GetStoreMenuUseCase`, `CatalogController`, `CatalogDtoMapper`.
- Methods/Variables: `camelCase` — `execute()`, `fetchCategories()`, `storeId`, `displayOrder`.
- Constants / Enums: `UPPER_SNAKE_CASE` — `CATEGORY_NOT_FOUND`, `GLUTEN_FREE`, `VEGAN`.
- Packages: `com.ordera.modules.catalog.<layer>`.

**Error Handling:**
- Ném `BusinessException(CatalogErrorCode.<ERROR_CODE>)`.
- Controllers trả về Envelope chuẩn `ApiResponse<T>`.

**Testing:**
- Framework: JUnit 5 + Mockito + AssertJ.
- Structure: AAA (Arrange - Act - Assert).
- Naming: `should_<expectedResult>_when_<scenario>()`.

# 4. Contracts

## 4.1 UseCase Interfaces

### Interface: `GetCategoriesUseCase`
```java
List<CategoryResponse> execute(UUID storeId);
// pre: storeId != null; tenantId from TenantContext != null
// post: returns list of categories ordered by displayOrder asc, each with its subcategories
// throws: BusinessException(STORE_NOT_FOUND) when storeId is invalid or not in tenant
```

### Interface: `GetSubcategoriesUseCase`
```java
List<SubcategoryResponse> execute(UUID categoryId);
// pre: categoryId != null; tenantId from TenantContext != null
// post: returns list of subcategories belonging to categoryId ordered by displayOrder asc
// throws: BusinessException(CATEGORY_NOT_FOUND) when category does not exist in tenant
```

### Interface: `GetStoreMenuUseCase`
```java
StoreMenuResponse execute(UUID storeId);
// pre: storeId != null; tenantId from TenantContext != null
// post: returns hierarchical menu tree (Categories -> Subcategories -> Products) with pricing and dietary tags
// throws: BusinessException(STORE_NOT_FOUND) when storeId is invalid or not in tenant
```

### Interface: `GetProductDetailUseCase`
```java
ProductDetailResponse execute(UUID productId);
// pre: productId != null; tenantId from TenantContext != null
// post: returns product detail with originalPrice, piecesText, dietaryTags and modifier groups
// throws: BusinessException(PRODUCT_NOT_FOUND) when product does not exist or unavailable
```

### Interface: `GetProductModifiersUseCase`
```java
List<ModifierGroupResponse> execute(UUID productId);
// pre: productId != null; tenantId from TenantContext != null
// post: returns list of modifier groups and detailed options for product
// throws: BusinessException(PRODUCT_NOT_FOUND) when product does not exist or unavailable
```

### Interface: `GetPromotionBannersUseCase`
```java
List<PromotionBannerResponse> execute(UUID storeId);
// pre: storeId != null; tenantId from TenantContext != null
// post: returns active banners applicable for storeId (store_id = storeId OR store_id IS NULL)
// throws: BusinessException(STORE_NOT_FOUND) when storeId is invalid or not in tenant
```

### Interface: `SearchProductsUseCase`
```java
List<ProductSummaryResponse> execute(UUID storeId, String query);
// pre: storeId != null, query != null && query.trim().length() >= 2
// post: returns matching available products
// throws: BusinessException(INVALID_QUERY_PARAM) when query < 2 chars
// throws: BusinessException(STORE_NOT_FOUND) when storeId is invalid
```

# 10. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|:---:|---|
| N+1 query khi load thực đơn cây phân cấp | High | Sử dụng batch fetch: lấy toàn bộ categories ➜ lấy toàn bộ subcategories qua `findByCategoryIdIn` ➜ lấy toàn bộ products khả dụng của tenant ➜ ghép cây trên bộ nhớ (In-memory tree assembly). |
| Sai lệch dữ liệu giữa các tenant | Critical | Luôn đọc `tenantId` từ `TenantContext.getTenantId()`. Repository luôn có điều kiện `tenantId`. |
| Parse lỗi JSONB `dietary_tags` | Medium | MapStruct / Helper method phòng thủ với fallback mảng rỗng `Collections.emptyList()`. |
