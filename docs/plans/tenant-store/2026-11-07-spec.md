# Feature Specification: Phân Hệ Cửa Hàng, Chi Nhánh, Bàn Ăn & Thiết Bị Kiosk (Tenant & Store Module)

## 1. Tầm nhìn & Mục tiêu Nghiệp vụ (Business Goal & Scope)
Phân hệ Tenant & Store là phân hệ nền tảng (Foundation Module) của nền tảng Ordera Multi-Tenant Loyalty & Ordering Platform. Phân hệ này chịu trách nhiệm quản trị:
- Cấu hình thương hiệu/đại lý F&B (`tenants`): Nhận diện thương hiệu (logo, slogan, màu sắc hex, hotline, tỷ lệ VAT mặc định, đơn vị tiền tệ).
- Quản lý danh sách chi nhánh cửa hàng (`stores`): Vị trí địa lý GPS (latitude, longitude), bán kính giao hàng, phí giao hàng, giờ mở cửa, năng lực phục vụ (Dine-in, Takeaway, Delivery), tính toán khoảng cách GPS bằng công thức Haversine.
- Quản lý bàn ăn tại quán (`store_tables`): Sức chứa, khu vực (zone), trạng thái bàn và giải mã token mã QR dán trên bàn (ví dụ: `QR-LINN-SENTRUM-T05` hoặc `qr_linn_sentrum_table_05`).
- Cửa hàng yêu thích của khách hàng (`customer_favorite_stores`): Đánh dấu/bỏ đánh dấu điểm bán yêu thích của từng khách hàng theo từng thương hiệu.
- Thiết bị Kiosk cảm ứng tại quầy (`kiosk_devices`): Quản lý tình trạng máy in bill, máy quẹt thẻ, heartbeat và timeout phiên.

## 3. Danh mục 7 API Hợp đồng Nghiệp vụ

| STT | Endpoint | Method | Use Case | Mô tả & Header bắt buộc |
|---|---|:---:|---|---|
| **1.1** | `/api/v1/tenants/current` | `GET` | `GetTenantInfoUseCase` | Lấy cấu hình thương hiệu hiện tại theo `X-Tenant-ID`. |
| **1.2** | `/api/v1/stores` | `GET` | `GetStoresListUseCase` | Danh sách chi nhánh kèm khoảng cách GPS Haversine, lọc hình thức phục vụ (`fulfillmentType`), tìm kiếm `keyword`. Header `X-Tenant-ID`, tùy chọn `Authorization`/`X-User-ID`. |
| **1.3** | `/api/v1/stores/{storeId}` | `GET` | `GetStoreDetailUseCase` | Chi tiết một chi nhánh (bán kính giao, phí giao, giờ mở cửa). Header `X-Tenant-ID`. |
| **1.4** | `/api/v1/stores/{storeId}/tables` | `GET` | `GetStoreTablesUseCase` | Danh sách bàn ăn tại chi nhánh chỉ định. Header `X-Tenant-ID`. |
| **1.5** | `/api/v1/stores/tables/qr/{qrToken}` | `GET` | `ResolveTableQrUseCase` | Giải mã mã QR bàn ăn (ví dụ `QR-LINN-SENTRUM-T05` hoặc `qr_linn_sentrum_table_05`) ra thông tin bàn và chi nhánh. |
| **1.6** | `/api/v1/stores/{storeId}/favorite` | `POST` / `DELETE` | `ToggleFavoriteStoreUseCase` | Bật/tắt lưu chi nhánh vào danh sách yêu thích của hội viên. |
| **1.7** | `/api/v1/stores/favorites` | `GET` | `GetFavoriteStoresUseCase` | Danh sách các chi nhánh yêu thích của hội viên hiện tại. |
| *(Phụ trợ)* | `/api/v1/stores/fulfillment-options` | `GET` | `GetStoreDetailUseCase` / Context | Trả về các hình thức phục vụ và khung giờ (ASAP / Schedule). |

## 4. Quy tắc Nghiệp vụ Chi tiết (Business Logic Rules)

1. **Công thức khoảng cách GPS (Haversine Formula):**
   - Áp dụng khi `latitude` và `longitude` người dùng được cung cấp trong query params của API 1.2.
   - Bán kính Trái Đất: $R = 6371.0\text{ km}$.
   - Công thức:
     $$d = 2R \cdot \arcsin\left(\sqrt{\sin^2\left(\frac{\Delta\varphi}{2}\right) + \cos(\varphi_1)\cos(\varphi_2)\sin^2\left(\frac{\Delta\lambda}{2}\right)}\right)$$
   - Làm tròn 2 chữ số thập phân (`distanceKm`), sắp xếp danh sách cửa hàng theo thứ tự khoảng cách tăng dần (gần nhất lên đầu).

2. **Giải mã mã QR Bàn Ăn (`ResolveTableQrUseCase`):**
   - Tìm kiếm `StoreTable` theo `qr_code_token` và kiểm tra khớp với `tenant_id` hiện tại.
   - Hỗ trợ định dạng hoa/thường hoặc token chính xác lưu trong DB (`QR-LINN-SENTRUM-T05`, `qr_linn_sentrum_table_05`).
   - Nếu không tìm thấy, ném ngoại lệ `InvalidQrTokenException` (Mã lỗi HTTP 404 với error code `INVALID_QR_TOKEN`).

3. **Multi-Tenant Isolation & IDOR Prevention:**
   - Mọi truy vấn bắt buộc phải có `tenant_id` từ `TenantContext.getTenantId()`.
   - Nếu thiếu header `X-Tenant-ID` hoặc context rỗng, ném `TenantHeaderMissingException` (Mã lỗi HTTP 400 với error code `TENANT_HEADER_MISSING`).
   - Mọi thao tác tìm kiếm theo `storeId`, `tableId` đều phải kèm điều kiện `tenant_id = current_tenant_id` để ngăn chặn 100% việc truy cập chéo giữa các thương hiệu.

4. **Quản lý Yêu thích (`customer_favorite_stores`):**
   - Bảng liên kết `(tenant_id, user_id, store_id)` có ràng buộc UNIQUE.
   - Thao tác `POST` thêm yêu thích (idempotent nếu đã tồn tại).
   - Thao tác `DELETE` gỡ yêu thích nếu đã tồn tại.

## 5. Chuẩn Hóa Phản Hồi & Lỗi (RFC 7807 Error Envelope)

Mọi API response đều được bọc trong `ApiResponse<T>`:
```json
{
  "success": true,
  "message": "Stores retrieved successfully",
  "data": [...],
  "timestamp": "2026-11-07T15:15:00.000Z"
}
```

Khi xảy ra lỗi, `GlobalExceptionHandler` trả về cấu trúc lỗi chuẩn:
```json
{
  "success": false,
  "error": {
    "code": "STORE_NOT_FOUND",
    "message": "Chi nhánh với ID '...' không tồn tại trong thương hiệu này.",
    "details": null
  },
  "timestamp": "2026-11-07T15:15:00.000Z"
}
```

Các mã lỗi chuẩn:
- `TENANT_HEADER_MISSING` (400)
- `INVALID_QUERY_PARAM` (400)
- `TENANT_NOT_FOUND` (404)
- `STORE_NOT_FOUND` (404)
- `TABLE_NOT_FOUND` (404)
- `INVALID_QR_TOKEN` (404)
- `UNAUTHORIZED` (401)

## 6. Chiến lược Kiểm thử (Testing Strategy)
- **Unit Tests (AAA Pattern):**
  - `GetTenantInfoUseCaseTest`: Kiểm thử thành công và ném `TenantNotFoundException`.
  - `GetStoresListUseCaseTest`: Kiểm thử tính khoảng cách Haversine chính xác, lọc `fulfillmentType`, sắp xếp khoảng cách.
  - `GetStoreDetailUseCaseTest`: Kiểm thử lấy chi tiết và ném `StoreNotFoundException`.
  - `ResolveTableQrUseCaseTest`: Kiểm thử giải mã QR token thành công và ném `InvalidQrTokenException`.
  - `ToggleFavoriteStoreUseCaseTest`: Kiểm thử thêm/xóa yêu thích.
- **WebMvc Controller Tests:**
  - `TenantControllerTest`: Kiểm thử endpoint `/api/v1/tenants/current` trả về 200 OK và xử lý lỗi thiếu header.
  - `StoreControllerTest`: Kiểm thử danh sách chi nhánh, chi tiết chi nhánh, giải mã QR và yêu thích cửa hàng.
