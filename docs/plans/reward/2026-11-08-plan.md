# 1. Context

**Problem:**  
Hệ thống Ordera cần phân hệ Ví Voucher, Đổi Thưởng và Ưu Đãi Giỏ Hàng hoàn chỉnh theo Clean Architecture 4 lớp. Phân hệ này cho phép khách hàng tra cứu ví ưu đãi (`My Rewards`), đổi điểm lấy voucher hoặc cốc giữ nhiệt Tumbler (`Get More Rewards`) với cơ chế Redisson Distributed Lock chống gian lận và race condition, và áp dụng ưu đãi vào giỏ hàng tại màn hình Checkout với quy tắc kết hợp nghiêm ngặt (tối đa 1 voucher + 1 quà hiện vật).

**Affected Modules:**  
- `com.ordera.modules.reward` — Phân hệ chính chứa Domain, Application, Infrastructure, Presentation.
- `com.ordera.modules.loyalty` — Cung cấp `AccruePointsUseCase` để ghi sổ cái trừ điểm và cập nhật hạng thành viên.
- `com.ordera.modules.order` — Bảng `carts` và `cart_items` được tương tác gián tiếp qua `CartOfferPort`.
- `com.ordera.config` — `SecurityConfig` (phân quyền endpoints `/api/v1/rewards/**` và `/api/v1/cart/**`).

**Non-Goals:**  
- Không sửa đổi trực tiếp logic thanh toán tiền mặt/Stripe trong module `order`.
- Không thay đổi bảng vật lý `points_ledger` (sổ cái bất biến phân vùng).
- Không tạo các Exception classes riêng lẻ ngoài `RewardErrorCode` + `BusinessException`.

# 2. Constraints

**Language:** Java 21 LTS, Spring Boot 3.3.5  
**Architecture:** Clean Architecture 4 Layers (Domain -> Application -> Infrastructure -> Presentation)  

**Rules:**  
- Multi-Tenant Isolation bắt buộc: Lọc mọi query theo `tenant_id` từ `TenantContext` hoặc header `X-Tenant-ID`.
- Zero Magic Numbers/Strings: Mọi hằng số khai báo tập trung trong `RewardConstants`.
- Anti-God Method: Mỗi phương thức `execute()` điều phối không quá 30–40 dòng; tách logic thành private helper methods có tên rõ nghĩa.
- Redisson Lock: Giải phóng khóa an toàn trong khối `finally`; DB transaction chạy bên trong lock boundary.
- Zero Hardcoded Strings trong Controller: Phản hồi chuẩn qua `ApiResponse.ok(RewardMessages.MSG_*, data)`.
- Không vi phạm nguyên tắc SOLID, cấu trúc kiểm thử AAA (Arrange - Act - Assert).

# 3. Conventions

**Naming:**  
- Classes: `PascalCase` (`RedeemVoucherUseCaseImpl`, `RewardController`, `CartOfferAdapter`)
- Methods/Variables: `camelCase` (`validateStockQuantity`, `userVoucherId`)
- Constants: `UPPER_SNAKE_CASE` (`MAX_VOUCHERS_PER_ORDER`, `LOCK_ACQUIRE_TIMEOUT_SEC`)
- Packages: `com.ordera.modules.reward.*`

**Error Handling:**  
- Định nghĩa tập trung trong `RewardErrorCode` (implement `ErrorCode`).
- Ném lỗi thông qua `throw new BusinessException(RewardErrorCode.<ERROR_CODE>, optionalMessage, optionalDetails)`.
- Tự động bắt bởi `GlobalExceptionHandler` trả về chuẩn RFC-7807/Ordera ApiResponse format.

**Logging:**  
- SLF4J qua `@Slf4j`. Structured log: `log.info("Member {} redeemed voucher {} successfully", memberId, voucherId)`.
- Ghi log warn khi không acquire được Redisson lock.

**Testing:**  
- Framework: JUnit 5, Mockito, AssertJ.
- Structure: AAA (Arrange - Act - Assert), tên hàm: `should_<expected>_when_<condition>()`.
- Coverage: 100% pass trên kịch bản đủ điểm, thiếu điểm, hết tồn kho quà và race condition đồng thời.

# 4. Contracts

## 4.1 Interface: `CartOfferPort`
```
findCartByIdAndTenantId(cartId: UUID, tenantId: UUID): Optional<CartOfferDetails>
  - pre: cartId != null, tenantId != null
  - post: trả về chi tiết giỏ hàng kèm danh sách items và subtotal tính toán
  - throws: không throw ngoại lệ, trả Optional.empty() nếu không tìm thấy

updateAppliedVoucher(cartId: UUID, tenantId: UUID, voucherCode: String): void
  - pre: cartId, tenantId, voucherCode hợp lệ
  - post: cập nhật carts.applied_voucher_code = voucherCode

updateAppliedGift(cartId: UUID, tenantId: UUID, giftId: UUID): void
  - pre: cartId, tenantId, giftId hợp lệ
  - post: cập nhật carts.applied_gift_id = giftId

clearAppliedVoucher(cartId: UUID, tenantId: UUID): void
  - pre: cartId, tenantId hợp lệ
  - post: cập nhật carts.applied_voucher_code = null

clearAppliedGift(cartId: UUID, tenantId: UUID): void
  - pre: cartId, tenantId hợp lệ
  - post: cập nhật carts.applied_gift_id = null
```

## 4.2 UseCase Interfaces
```
GetMyRewardsWalletUseCase.execute(status: String, type: String): MyRewardsWalletResponse
  - pre: người dùng đã đăng nhập (SecurityUtils.getCurrentUserId() != null), TenantContext hợp lệ
  - post: trả về danh sách vouchers và gifts trong ví
  - throws: BusinessException(UNAUTHORIZED), BusinessException(TENANT_HEADER_MISSING)

GetRewardsCatalogUseCase.execute(): RewardsCatalogResponse
  - pre: người dùng đã đăng nhập, TenantContext hợp lệ
  - post: trả về danh mục vouchers, gifts kèm trạng thái canAfford và pointsNeeded
  - throws: BusinessException(UNAUTHORIZED), BusinessException(TENANT_HEADER_MISSING)

RedeemVoucherUseCase.execute(voucherId: UUID): RedeemVoucherResponse
  - pre: voucherId != null, người dùng có đủ điểm
  - post: trừ điểm trong sổ cái, tạo user_voucher status AVAILABLE
  - throws: BusinessException(VOUCHER_NOT_FOUND), BusinessException(INSUFFICIENT_POINTS), BusinessException(CONCURRENT_TRANSACTION_LOCK)

RedeemPhysicalGiftUseCase.execute(giftId: UUID): RedeemGiftResponse
  - pre: giftId != null, người dùng có đủ điểm, gift.stockQuantity > 0
  - post: giảm tồn kho quà, sinh mã 8 ký tự, trừ điểm trong sổ cái, tạo user_gift_redemption status PENDING
  - throws: BusinessException(GIFT_NOT_FOUND), BusinessException(GIFT_OUT_OF_STOCK), BusinessException(INSUFFICIENT_POINTS), BusinessException(CONCURRENT_TRANSACTION_LOCK)

GetRewardsSummaryUseCase.execute(): RewardsSummaryResponse
  - pre: người dùng đã đăng nhập, TenantContext hợp lệ
  - post: đếm activeVouchersCount, availableGiftsCount, totalAvailableRewards

GetAvailableOffersForCartUseCase.execute(cartId: UUID): AvailableOffersResponse
  - pre: cartId != null, giỏ hàng tồn tại
  - post: trả về subtotalAmount, danh sách vouchers kèm isApplicable và ineligibilityReason, danh sách gifts

ValidatePromoCodeUseCase.execute(request: ValidatePromoCodeRequest): ValidatePromoCodeResponse
  - pre: request.code non-blank, request.cartId != null
  - post: kiểm tra tính hợp lệ và trả về discountAmount tính toán được
  - throws: BusinessException(PROMO_CODE_NOT_FOUND), BusinessException(PROMO_CODE_INELIGIBLE)

ApplyVoucherToCartUseCase.execute(request: ApplyVoucherRequest): CartVoucherCalculationResponse
  - pre: request.cartId != null, request.voucherCode non-blank
  - post: chuyển user_voucher sang IN_USE, gán vào cart, trả về bảng tổng tiền (subtotal, discount, vat, finalTotal)
  - throws: BusinessException(VOUCHER_NOT_FOUND), BusinessException(MINIMUM_ORDER_NOT_MET), BusinessException(INVALID_REWARD_COMBINATION)

RemoveVoucherFromCartUseCase.execute(request: RemoveVoucherRequest): CartVoucherCalculationResponse
  - pre: request.cartId != null, request.voucherCode non-blank
  - post: chuyển user_voucher sang AVAILABLE, gỡ khỏi cart, trả về bảng tổng tiền mới

ApplyGiftToCartUseCase.execute(request: ApplyGiftRequest): CartGiftCalculationResponse
  - pre: request.cartId != null, request.rewardGiftId != null
  - post: chuyển user_gift_redemption sang SELECTED, gán vào cart
  - throws: BusinessException(GIFT_NOT_FOUND), BusinessException(INVALID_REWARD_COMBINATION)

RemoveGiftFromCartUseCase.execute(request: RemoveGiftRequest): CartGiftCalculationResponse
  - pre: request.cartId != null, request.rewardGiftId != null
  - post: chuyển user_gift_redemption sang PENDING, gỡ khỏi cart
```

# 5. Target Architecture & Flow

```
HTTP Request (/api/v1/rewards/*, /api/v1/cart/*)
       │
       ▼
[SecurityFilterChain + JwtAuthenticationFilter]
       │
       ▼
[RewardController / CartOfferController]
       │
       ▼
[UseCase Implementation (Orchestrator)]
       ├── 1. Acquire Redisson Lock (RLock / MultiLock in try block)
       ├── 2. Validate tenant, user, points & stock
       ├── 3. Execute DB Transaction (via PlatformTransactionManager / @Transactional)
       │       ├── Update vouchers / user_vouchers / loyalty_gifts / user_gift_redemptions
       │       ├── Call AccruePointsUseCase (Points Ledger deduction)
       │       └── Update Cart via CartOfferPort
       ├── 4. Finally: Release Redisson Lock (if held by current thread)
       │
       ▼
[RewardDtoMapper (MapStruct)]
       │
       ▼
ApiResponse.ok(RewardMessages.MSG_*, DTO) -> HTTP 200/201
```

# 9. Edge Cases

| # | Edge Case Scenario | Expected Behavior | Handled In |
|---|---|---|---|
| 1 | Khách hàng bấm đúp đổi quà liên tục trong 1 giây | Redisson lock chặn giao dịch thứ 2, trả về 409 `CONCURRENT_TRANSACTION_LOCK` | Task 4, Task 5 |
| 2 | Món quà hiện vật chỉ còn đúng 1 cái trong kho | Luồng đầu tiên đổi thành công, luồng thứ 2 nhận 409 `GIFT_OUT_OF_STOCK` | Task 5 |
| 3 | Khách cố tình áp dụng 2 voucher vào cùng 1 giỏ hàng | Chặn và ném lỗi 422 `INVALID_REWARD_COMBINATION` | Task 7 |
| 4 | Giỏ hàng chưa đạt giá trị tối thiểu (`subtotal < min_order_value`) | Trả về `isApplicable: false` hoặc ném 422 `MINIMUM_ORDER_NOT_MET` | Task 6, Task 7 |
| 5 | Voucher đã hết hạn (`valid_until < now()`) | Ném lỗi 422 `VOUCHER_EXPIRED` | Task 6, Task 7 |
| 6 | Gỡ voucher khỏi giỏ hàng nhưng voucher chưa từng được áp dụng | Ném lỗi 404 `VOUCHER_NOT_FOUND` hoặc trả về giỏ nguyên vẹn an toàn | Task 7 |
| 7 | Thiếu Header `X-Tenant-ID` hoặc chưa đăng nhập JWT | Ném 400 `TENANT_HEADER_MISSING` hoặc 401 `UNAUTHORIZED` | Task 3 - Task 8 |

# 10. Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|---|:---:|:---:|---|
| Cạn kiệt Connection Pool DB khi giữ Redisson lock lâu | High | Low | Giữ lock timeout ngắn (3s/5s), giải phóng trong `finally`, mở transaction DB sau khi đã giữ lock thành công |
| Deadlock khi lock đồng thời member và gift | High | Low | Luôn acquire lock theo thứ tự cố định (member lock trước, gift lock sau) hoặc dùng Redisson MultiLock |
| Lệch số dư điểm giữa cache `member_profiles` và `points_ledger` | Critical | Low | Giao toàn bộ việc cập nhật điểm và ghi sổ cái cho `AccruePointsUseCase` trong cùng 1 transaction |
