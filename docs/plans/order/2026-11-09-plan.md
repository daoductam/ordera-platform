# 1. Context

**Problem:**
Khách hàng F&B trên ứng dụng Ordera Mobile Web PWA và Kiosk cần một quy trình đặt món hoàn chỉnh, mượt mà và an toàn: từ quản lý giỏ hàng tạm thời, áp dụng tùy chọn món (modifiers), tính toán chi phí minh bạch (VAT 15%, tiền tip, giảm giá voucher, điểm thưởng tích lũy), chốt đơn thanh toán bảo vệ giao dịch (ACID, chống race-condition qua Redisson, chống trừ tiền lặp qua Idempotency-Key), theo dõi tiến trình chế biến tại bếp đến nhận biên nhận điện tử E-Receipt qua Email.

**Affected Modules:**
- `order`: Phân hệ trung tâm quản lý toàn bộ vòng đời giỏ hàng, đơn hàng, hóa đơn điện tử.
- `loyalty`: Nhận yêu cầu cộng điểm thưởng qua `AccruePointsUseCase` sau khi đơn hàng thanh toán thành công.
- `reward`: Cập nhật trạng thái voucher sở hữu sang `USED` và liên kết với `orders`.
- `catalog`: Tra cứu thông tin món ăn và modifiers khi kiểm tra giỏ hàng.
- `common`: Tái sử dụng `TenantContextHolder`, `SecurityUtils`, `BaseEntity`, `BaseTenantEntity`, `ApiResponse`.

**Non-Goals:**
- Tích hợp cổng thanh toán thực tế bên thứ ba (Vipps/Stripe/ApplePay gateway live SDK) — xử lý thanh toán mô phỏng/mock theo chuẩn thiết kế.
- Quản trị viên can thiệp sửa đổi giá món ăn trong quá khứ.

# 2. Constraints

**Language & Stack:** Java 21 LTS, Spring Boot 3.3.5, Spring Data JPA, PostgreSQL 16 (RLS), Redis 7 & Redisson 3.37.0, Spring Mail, MapStruct, Lombok.  
**Architecture:** Clean Architecture 4 lớp phân tầng chặt chẽ: `domain/`, `application/`, `infrastructure/`, `presentation/`.

**Rules:**
- **Tuyệt đối cấm Magic Numbers / Magic Strings:** Toàn bộ hằng số nghiệp vụ, tỷ lệ VAT, khóa Redis, thời gian TTL, độ dài giới hạn phải khai báo tập trung tại `OrderConstants.java`. Toàn bộ thông điệp phản hồi phải tập trung tại `OrderMessages.java`.
- **Cấm tạo Exception classes riêng lẻ:** Mọi ngoại lệ nghiệp vụ phải ném thông qua `BusinessException(OrderErrorCode.*)`.
- **Chống God Method (Orchestrator Pattern):** Hàm `execute()` trong các UseCaseImpl chỉ giữ vai trò điều phối luồng từ 30-40 dòng code; chia nhỏ thành các private helper methods.
- **Null-Safety & Nesting Depth <= 3:** Luôn kiểm tra null an toàn cho `tip`, `comment`, `appliedVoucherCode`, `tableNumber`.
- **Multi-Tenant Isolation (Default ON):** Mọi truy vấn database nghiệp vụ đều phải lọc theo `tenant_id` qua `TenantContextHolder` (ngăn chặn 100% IDOR).
- **Độ chính xác tài chính số học:** Sử dụng `BigDecimal` với scale = 2 và `RoundingMode.HALF_UP`.

# 3. Conventions

**Naming:**
- Classes: `PascalCase` — e.g. `CheckoutOrderUseCaseImpl`, `OrderCalculationUtils`, `OrderJpaEntity`
- Methods/Variables: `camelCase` — e.g. `calculateVatAmount()`, `pointsToEarn`
- Constants: `UPPER_SNAKE_CASE` — e.g. `VAT_RATE`, `IDEMPOTENCY_KEY_TTL_HOURS`
- Package: `com.ordera.modules.order.*`

**Error Handling:**
- Ném `BusinessException` với `OrderErrorCode` (triển khai `ErrorCode` interface gồm `HttpStatus`, `code`, `message`).
- Định dạng phản hồi lỗi chuẩn RFC 7807 thông qua GlobalExceptionHandler.

**Logging:**
- Sử dụng `@Slf4j` với structured logging: `log.info("checkout_order_initiated tenantId={} userId={} cartId={}", tenantId, userId, cartId)`.

**Testing:**
- JUnit 5 + Mockito, cấu trúc AAA (Arrange - Act - Assert).
- Tên hàm test: `should_<expected>_when_<condition>()`.
- Độ chính xác số học BigDecimal, công thức VAT 15%, voucher discount và điểm thưởng đạt 100% pass.

# 4. Contracts

## 4.1 Interface: `OrderCalculationUtils`
```
calculateSubtotal(items: List<CartItem>): BigDecimal
  - pre: items not null
  - post: returns sum of (unitPrice + modifiers) * quantity, scale = 2

calculateVat(totalAmount: BigDecimal): BigDecimal
  - pre: totalAmount not null, >= 0
  - post: returns totalAmount * 15 / 115, scale = 2, RoundingMode.HALF_UP

calculateTotal(subtotal: BigDecimal, discount: BigDecimal, tip: BigDecimal): BigDecimal
  - pre: subtotal >= 0, discount >= 0, tip >= 0
  - post: returns max(0, subtotal - discount) + tip, scale = 2

calculatePointsToEarn(subtotal: BigDecimal, discount: BigDecimal, tierRate: BigDecimal): int
  - pre: subtotal >= 0, discount >= 0, tierRate > 0
  - post: returns floor((subtotal - discount) * tierRate) as integer; excludes tip
```

## 4.2 Interface: `CartService`
```
getCart(tenantId: UUID, userId: UUID, storeId: UUID): CartResponse
  - pre: tenantId not null
  - post: returns CartResponse from Redis or Postgres fallback

addItem(tenantId: UUID, userId: UUID, request: AddCartItemRequest): CartResponse
  - pre: tenantId not null, productId valid, quantity in [1, 99]
  - post: adds or merges item in cart, updates Redis TTL 7 days

updateItemQuantity(tenantId: UUID, userId: UUID, itemId: UUID, quantity: int): CartResponse
  - pre: itemId exists in cart; quantity >= 0
  - post: updates quantity; if 0, removes item

deleteItem(tenantId: UUID, userId: UUID, itemId: UUID): CartResponse
  - pre: itemId exists in cart
  - post: removes item from cart

updateComment(tenantId: UUID, userId: UUID, comment: String): CartResponse
  - pre: comment length <= 200
  - post: updates allergy / special instruction comment in cart
```

## 4.3 Interface: `PreviewCheckoutCalculationUseCase`
```
execute(tenantId: UUID, userId: UUID, request: PreviewCheckoutRequest): PreviewCheckoutResponse
  - pre: cart exists and is not empty
  - post: returns subtotal, discount, tip, VAT 15%, total, and pointsToEarn
  - throws: BusinessException(CART_EMPTY) when cart has 0 items
```

## 4.4 Interface: `CheckoutOrderUseCase`
```
execute(tenantId: UUID, userId: UUID, idempotencyKey: String, request: CheckoutOrderRequest): CheckoutOrderResponse
  - pre: request valid, cart not empty
  - post: creates order, deducts voucher, accrues points, flushes cart, saves idempotency key
  - throws: BusinessException(IDEMPOTENT_OPERATION_CONFLICT) if request already processed
```

# 9. Edge Cases & Boundary Handling

| Edge Case | Mô Tả | Xử Lý Tại Task |
|---|---|---|
| **Giỏ hàng rỗng khi Checkout/Preview** | Khách bấm preview hoặc checkout khi giỏ hàng chưa có món | Ném `BusinessException(OrderErrorCode.CART_EMPTY)` (Task 8, 9) |
| **Voucher không đủ đơn hàng tối thiểu** | Subtotal < voucher `min_order_value` | Ném `BusinessException(OrderErrorCode.MINIMUM_ORDER_VALUE_NOT_MET)` (Task 8, 9) |
| **Thanh toán trùng lặp (Double click)** | Khách bấm Pay nhiều lần liên tiếp | Bị chặn bởi `Idempotency-Key` (409) hoặc Redisson Lock (Task 9) |
| **Tiền tip null hoặc 0.00** | Khách không nhập tiền tip hoặc truyền null | `order.getTip() != null ? order.getTip() : BigDecimal.ZERO` (Task 3, 9) |
| **Ghi chú dị ứng quá dài** | Khách nhập ghi chú > 200 ký tự | Validate `@Size(max=200)` ném lỗi 422 `OrderErrorCode.INVALID_INPUT` (Task 7, 12) |
| **Reorder món ăn đã ngừng kinh doanh** | Món trong đơn cũ không còn trong bảng products | Ném `BusinessException(OrderErrorCode.STOCK_UNAVAILABLE)` (Task 10) |
| **Lấy đơn hàng của người khác (IDOR)** | User A truyền orderId của User B | Kiểm tra `order.getUserId().equals(currentUserId)` nếu không ném 404 `ORDER_NOT_FOUND` (Task 10) |

# 10. Risks & Mitigations

- **Risk 1: Deadlock hoặc giữ kết nối database quá lâu khi chiếm giữ Redisson Lock.**  
  *Mitigation:* Chiếm giữ lock với timeout ngắn (acquire 5s, lease 10s), chỉ mở transaction sau khi đã acquire lock thành công.
- **Risk 2: Sai lệch làm tròn số tiền cent/øre trong VAT và Discount.**  
  *Mitigation:* Chuẩn hóa mọi phép tính dùng `BigDecimal` với scale = 2 và `RoundingMode.HALF_UP`. Kiểm thử unit test mọi trường hợp lẻ tiền.
- **Risk 3: Xung đột tên file/mapper với reward module.**  
  *Mitigation:* Package naming phân tầng độc lập `com.ordera.modules.order` hoàn toàn tách biệt.
