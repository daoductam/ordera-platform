# 1. Context

**Problem:**
Phân hệ Thẻ thành viên & Sổ cái điểm thưởng (Loyalty & Points Ledger Engine) là linh hồn của nền tảng Ordera, phục vụ tích lũy điểm thưởng theo 6 hạng thẻ (`New` $\rightarrow$ `Silver` $\rightarrow$ `Gold` $\rightarrow$ `Platinum` $\rightarrow$ `Diamond` $\rightarrow$ `Ruby`), đối soát kế toán điểm kép bất biến (chống gian lận điểm, cấm tuyệt đối `UPDATE/DELETE` trên `points_ledger`), khóa phân tán Redisson chống race-condition đồng thời, và tiếp nhận khiếu nại bù điểm hóa đơn sót.

**Affected Modules:**
- `backend/pom.xml`: Thêm dependency `redisson-spring-boot-starter:3.37.0`.
- `com.ordera.config`: Thêm `RedissonConfig.java` khởi tạo bean `RedissonClient`.
- `com.ordera.common.util`: Bổ sung `LoyaltyTierUtils.java` tính toán khoảng cách thăng hạng và % tiến độ.
- `com.ordera.modules.loyalty`: Triển khai 4 lớp Clean Architecture (Domain, Application, Infrastructure, Presentation) cho 6 API và động cơ thăng hạng.
- `com.ordera.modules.ledger`: Triển khai 4 lớp Clean Architecture cho sổ cái điểm phân vùng PostgreSQL range partitioning.

**Non-Goals:**
- Chưa triển khai giao diện Admin Portal xét duyệt thủ công khiếu nại `support_claims` (sẽ nằm ở phân hệ Backoffice Admin riêng).
- Chưa triển khai giao dịch trừ điểm đổi voucher (sẽ nằm ở phân hệ Reward gọi sang `AccruePointsUseCase`).

# 2. Constraints

**Language & Framework:** Java 21 LTS, Spring Boot 3.3.5 (Spring Security 6, Spring Data JPA, Redisson 3.37.0, MapStruct 1.5.5.Final, Lombok).  
**Architecture:** Clean Architecture 4 lớp (Presentation ➜ Application ➜ Domain ➜ Infrastructure).

**Rules:**
- **Độc lập tầng Domain:** Pure Java POJOs, không phụ thuộc Spring hay JPA.
- **Xử lý ngoại lệ chuẩn hóa:** Cấm tạo Exception classes riêng lẻ. Mọi lỗi nghiệp vụ loyalty đều định nghĩa trong `LoyaltyErrorCode` (implement `ErrorCode`) và ném qua `BusinessException`. Xóa bỏ `InvalidTierTransitionException` cũ.
- **Bất biến Sổ Cái (Immutability):** Không bao giờ `UPDATE` hay `DELETE` bảng `points_ledger`. Chỉ `INSERT` bản ghi mới.
- **Khóa Phân Tán Redisson:** Bắt buộc sử dụng `RLock` key `lock:tenant:{tenantId}:member:{memberId}` khi biến động điểm số.
- **Phân lập Multi-Tenant:** 100% các truy vấn cơ sở dữ liệu phải được lọc theo `tenantId` lấy từ `TenantContext.getTenantId()`.
- **Orchestrator Pattern:** Các UseCase `execute()` chỉ giữ vai trò điều phối các bước, phân rã logic thành private helper methods.

# 4. Contracts

## 4.1 UseCase Interfaces

### Interface: `GetMemberProfileUseCase`
```java
MemberProfileResponse execute();
// pre: User authenticated; TenantContext has tenantId
// post: returns MemberProfileResponse with points, tier, barcode, counters, notice flag
// throws: BusinessException(MEMBER_PROFILE_NOT_FOUND) when profile not found
```

### Interface: `UpdateProfileUseCase`
```java
UpdateProfileResponse execute(UpdateProfileRequest request);
// pre: request != null; User authenticated; TenantContext has tenantId
// post: updates profile and returns updated details
// throws: BusinessException(EMAIL_ALREADY_EXISTS) when email is taken in tenant
```

### Interface: `CompleteProfileUseCase`
```java
CompleteProfileResponse execute(CompleteProfileRequest request);
// pre: request != null; User authenticated
// post: completes missing profile info for new members
```

### Interface: `UploadAvatarUseCase`
```java
AvatarUploadResponse execute(MultipartFile file);
// pre: file != null; size <= 5MB; format in [jpeg, png, webp]
// post: stores avatar and returns URL
// throws: BusinessException(FILE_TOO_LARGE) when size > 5MB
// throws: BusinessException(UNSUPPORTED_IMAGE_FORMAT) when format invalid
```

### Interface: `GetTierDefinitionsUseCase`
```java
List<TierDefinitionResponse> execute();
// pre: TenantContext has tenantId
// post: returns list of 6 tier definitions ordered by tier_order asc
```

### Interface: `GetPointsLedgerHistoryUseCase`
```java
PageResponse<PointsLedgerEntryResponse> execute(Pageable pageable);
// pre: User authenticated; pageable != null
// post: returns paginated points ledger entries ordered by created_at desc
```

### Interface: `SubmitSupportClaimUseCase`
```java
SupportClaimResponse execute(SubmitSupportClaimRequest request);
// pre: request != null; orderDate within 30 days; receiptCode not duplicate
// post: creates support claim in PENDING status
// throws: BusinessException(RECEIPT_EXPIRED) when orderDate > 30 days ago
// throws: BusinessException(CLAIM_ALREADY_EXISTS) when receiptCode already registered
```

### Interface: `AccruePointsUseCase`
```java
PointsLedgerJpaEntity execute(AccruePointsCommand command);
// pre: command != null; member exists; tenantId valid
// lock: acquires Redisson lock:tenant:{tenantId}:member:{memberId}
// post: inserts points_ledger, updates member_profiles cache, auto-upgrades tier if threshold met
// throws: BusinessException(INSUFFICIENT_POINTS) when deducting more than current points
// throws: BusinessException(CONCURRENT_TRANSACTION_LOCK) when lock acquisition fails
```

# 8. Task Specifications

### Task 1: Redisson Config & Dependency
- **Files:** `backend/pom.xml`, `backend/src/main/java/com/ordera/config/RedissonConfig.java`.
- **Criteria:** Bean `RedissonClient` khởi tạo thành công kết nối tới Redis, hỗ trợ cấu hình single server an toàn.

### Task 2: Domain Models & ErrorCodes
- **Files:** `com.ordera.modules.loyalty.domain.exception.LoyaltyErrorCode`, `MemberTier`, `TransactionType`.
- **Criteria:** `LoyaltyErrorCode` implement `ErrorCode`, xóa `InvalidTierTransitionException`, đầy đủ enum types.

### Task 3: LoyaltyTierUtils
- **Files:** `com.ordera.common.util.LoyaltyTierUtils`.
- **Criteria:** `calculateTierProgress(currentTierId, lifetimePoints, tiers)` tính toán chính xác `pointsToNextTier`, `progressPercentage` (mốc 0, lưng chừng 300 $\rightarrow$ 50%, kịch trần Ruby $\rightarrow$ 100%).

### Task 4 & 5: Repositories & Mappers
- **Files:** `MemberProfileJpaRepository`, `TierDefinitionJpaRepository`, `SupportClaimJpaRepository`, `PointsLedgerJpaRepository`, `LoyaltyDtoMapper`, `LedgerMapper`.
- **Criteria:** Định nghĩa đúng các truy vấn lọc theo `tenantId`, map DTO và Entity mượt mà.

### Task 6: AccruePointsUseCase (Core Engine)
- **Files:** `AccruePointsUseCase`, `AccruePointsUseCaseImpl`, `AccruePointsCommand`.
- **Criteria:**
  - Lấy Redisson lock `lock:tenant:{tenantId}:member:{memberId}`.
  - Insert bản ghi mới vào `points_ledger` (bất biến, không update/delete).
  - Tự động thăng hạng thẻ khi `lifetime_points` đạt mốc `min_points_required` của bậc kế tiếp.
  - Ném `INSUFFICIENT_POINTS` nếu trừ vượt số dư. Giải phóng lock trong `finally`.

### Task 7: Member Profile UseCases
- **Files:** `GetMemberProfileUseCaseImpl`, `UpdateProfileUseCaseImpl`, `CompleteProfileUseCaseImpl`, `UploadAvatarUseCaseImpl`.
- **Criteria:** Trả về đầy đủ profile theo Figma 04.01-04.09, upload avatar kiểm tra dung lượng $\le 5\text{MB}$ và format JPEG/PNG/WebP.

### Task 8: History, Claims & Tiers UseCases
- **Files:** `GetPointsLedgerHistoryUseCaseImpl`, `SubmitSupportClaimUseCaseImpl`, `GetTierDefinitionsUseCaseImpl`.
- **Criteria:** Phân trang lịch sử ledger `createdAt DESC`, từ chối claim quá 30 ngày (`RECEIPT_EXPIRED`) hoặc trùng mã (`CLAIM_ALREADY_EXISTS`).

### Task 9 & 10: Presentation Controllers
- **Files:** `MemberLoyaltyController`, `SupportClaimController`, DTOs.
- **Criteria:** Envelope `ApiResponse<T>`, RFC 7807, `@Valid`, routes khớp 100% với tài liệu API design.

### Task 11 & 12: Unit Tests & Verification
- **Files:** Unit tests kiểm tra đầy đủ 100% coverage các luồng chính, thăng hạng tự động, concurrency lock và immutability.

# 9. Edge Cases

| # | Edge Case | Expected Behavior | Handled In |
|---|---|---|---|
| 1 | Hội viên đạt mốc Ruby (4000+ điểm) | `pointsToNextTier = 0`, `nextTierName = "Ruby"`, `progressPercentage = 100.0` | Task 3 & 7 |
| 2 | Trừ điểm đổi voucher khi số dư không đủ | Ném `INSUFFICIENT_POINTS` (400) | Task 6 |
| 3 | Hai luồng cộng/trừ điểm cùng lúc cho 1 hội viên | Khóa Redisson ngăn race-condition, tuần tự hóa hoặc ném `CONCURRENT_TRANSACTION_LOCK` | Task 1 & 6 |
| 4 | Khiếu nại hóa đơn mua hơn 30 ngày trước | Ném `RECEIPT_EXPIRED` (422) kèm chi tiết `maxAllowedDays: 30` | Task 8 & 10 |
| 5 | Gửi khiếu nại với mã hóa đơn đã tồn tại trong tenant | Ném `CLAIM_ALREADY_EXISTS` (409) | Task 8 & 10 |
| 6 | Upload avatar file > 5MB hoặc sai định dạng (.exe, .pdf) | Ném `FILE_TOO_LARGE` (413) hoặc `UNSUPPORTED_IMAGE_FORMAT` (415) | Task 7 & 9 |
| 7 | Cố gắng gọi UPDATE/DELETE trên `points_ledger` | Bị chặn bởi logic kiến trúc và database trigger `trg_points_ledger_immutable` | Task 4 & 6 |

# 10. Risks & Mitigation

| Rủi ro | Mức độ | Biện pháp giảm thiểu |
|---|:---:|---|
| Xung đột Redisson với Spring Boot 3.3.5 | Trung bình | Tích hợp `redisson-spring-boot-starter:3.37.0` đã tải về cache local `.m2`, cấu hình bean tường minh trong `RedissonConfig`. |
| Deadlock khi giữ khóa phân tán | Thấp | Thiết lập `waitTime = 3s`, `leaseTime = 5s` và luôn unlock trong khối `finally { if (lock.isHeldByCurrentThread()) lock.unlock(); }`. |
| Rò rỉ dữ liệu chéo Tenant (IDOR) | Cao | 100% các truy vấn kiểm tra `tenantId` từ `TenantContext.getTenantId()`. |
